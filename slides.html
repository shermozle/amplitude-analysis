The toolkit10 min

Tool 1 of 3 · in the browser

What left the browser

Event Explorer

Chrome extension

Sits in the page and lists every event as it's sent, with its full property payload, plus your device ID and session ID. Your nearest Adobe habit is the Experience Platform debugger or a packet monitor.

Fallback

The site's own log

Gear button, bottom right, or Ctrl+Shift+D. The demo site logs every track() call it makes. Useful when you haven't got the extension installed, and useful in general when a site is instrumented well.

This answers one question: did it fire, and with what. Open your Order Placed and look at the Products array. One object per line item, which is where the cart analysis in the next act comes from.

The toolkit10 min

Tool 2 of 3 · in Amplitude, under Data

What Amplitude accepted

  • Ingestion DebuggerA live view of events arriving at the server, with the raw payload as received.
  • Why it's separateThe extension shows what left the browser. This shows what Amplitude kept. Blocked events, filtered properties and type mismatches only show up here.
  • The failure it catchesInstrumentation that looks perfect in the browser and produces nothing in a chart. Any gap between these two views is a configuration problem, not a code problem.

If the extension shows the event and this doesn't, where would you look first?

Tool 3 of 3 · the one you'll use most

One user's actual events

User Lookup gives you one person's events in order, with every property, and every user-property change marked where it happened. It's what you open when someone tells you a report is wrong.

Try this Search User Lookup for user ID 2003964661. Then log in on the site, as anyone, and look again.

Everyone who logs in becomes that same ID, because the site hardcodes one customer number. Eight people's sessions, one user profile, no error anywhere. That's a real implementation bug of a kind you will meet, and it's the opening example of session 4.

Four charts22 min

The four, and what they answer

The questionChartUsual Adobe routeWhere it differs
How many, broken down by whatData TableFreeform table Any property is available without being configured first, because there are no slots to allocate.
Where do people fall outFunnelFallout You set the conversion window and the step-order rule explicitly, and both change the answer.
What did they do nextJourneysFlow Starts from any event, not just a page, so you can begin at a failed address check.
How often, and for how longUser SessionsVisits metrics A session is a gap between events, set once per project, rather than a hit-based visit.

Amplitude asks you to pick the question type before you get a canvas. That's a real adjustment coming from a blank freeform table, and it's mostly a help: the chart knows what you're asking, so the controls are the ones you need.

Four charts22 min

When a number looks wrong today

  • dicount_appliedThe generator misspells it; the site spells it discount_applied. Two children under one parent, roughly half the data each. Group by either and you've quietly reported on half the cohort.
  • Products.brandOver 30 days you'll see Fossil and Michael Kors next to iPhones. The generated line items carry a fashion catalogue that can't be configured. Scope to today and it resolves.
  • [Amplitude] Page ViewedAutocapture sends that; the site also sends its own Page Viewed with more properties. Two near-identical names, side by side in the picker.
  • 21 live-only eventsNo generated history, so they look broken until someone uses the site. Checkout Step Completed is the one that bites hardest, and you'll hit it in a minute.

First question when a number surprises you: which sources feed this. Second question: which of the four things above is it. That habit transfers straight into a real implementation.

03

Funnel

  • New chart, Funnel: Product Viewed → Add to Cart → Checkout Started → Order Placed.
  • Change the conversion window from 1 day to 30 days and watch the conversion rate move. Same data, different question.
  • Group by Products.department.
  • Now insert Checkout Step Completed as step 4. Watch what happens to the whole funnel.
Done when You can explain why adding a step that obviously happens dropped conversion to nearly zero.

A funnel reports on whoever has every step. Where does that bite while two tools are running side by side?

Four charts22 min
04

Journeys

  • New chart, Journeys. Start from Address Checked.
  • Filter that starting event to the results where serviceability failed.
  • Read the branches out. Where do people go when the answer is no?
Done when You can name the two most common next steps after a failed address check.

Starting from an event rather than a page is the part worth noticing. A flow report anchored on URLs can't ask this question at all, because the failure isn't a page, it's a property value on an event.

Four charts22 min
05

User Sessions

  • New chart, User Sessions. Look at sessions per user and average session length.
  • Add a second series segmented to people who placed an order.
  • Compare the two.
Done when You can say whether purchasers take more sessions than everyone else, and roughly how many.

The session boundary is a project setting, a gap of inactivity, not a rule about hits. So "visits" and "sessions" are close cousins rather than the same measure, and the gap matters as soon as you try to reconcile two tools against each other.

Your chart

  • Before you touch Amplitude, write down one question you answer in Adobe today. One sentence. Two minutes.
  • Build one chart that answers it, using this data and any of the four types.

The gap is genuinely the more valuable outcome. A list of questions this taxonomy can't answer is the start of the requirements work, and I'd rather collect it from you than invent it.
